# 用户角色与兑换码系统说明

## 1. 角色分类及区分方式

### 1.1 角色分类

根据 `models/User.js` (第104-108行)，系统角色分为以下5类：

| 角色值 | 角色名称 | 说明 |
|--------|---------|------|
| 0 | 普通用户 | 默认角色 |
| 1 | VIP | VIP会员 |
| 2 | SVIP | 超级VIP会员 |
| 3 | 管理员 | 普通管理员 |
| 4 | 超级管理员 | 最高权限管理员 |

### 1.2 角色存储字段

- **主要字段**: `role` (Number类型)
- **VIP过期时间**: `vip_expire` 或 `vipExpireDate` (Date类型)
- **SVIP过期时间**: `svipExpireDate` (Date类型)

### 1.3 VIP/SVIP验证机制

系统提供了两个方法来验证用户身份：

#### isVip() 方法 (models/User.js 第238-245行)
```javascript
UserSchema.methods.isVip = function () {
  return (
    (this.role === 1 || this.role === 2) &&
    (this.vip_expire || this.vipExpireDate) &&
    (this.vip_expire > new Date() || this.vipExpireDate > new Date())
  );
};
```

**判定条件**：
1. 角色是 1 (VIP) 或 2 (SVIP)
2. 有过期时间字段
3. 过期时间在当前时间之后

#### isSvip() 方法 (models/User.js 第247-252行)
```javascript
UserSchema.methods.isSvip = function () {
  return (
    this.role === 2 && this.svipExpireDate && this.svipExpireDate > new Date()
  );
};
```

**判定条件**：
1. 角色是 2 (SVIP)
2. 有 svipExpireDate 字段
3. 过期时间在当前时间之后

## 2. 兑换码系统分析

### 2.1 兑换码类型

根据 `models/RedeemCode.js` (第12行)，支持以下类型：

| 类型 | 说明 |
|------|------|
| vip | VIP会员 |
| svip | SVIP会员 |
| balance | 余额 |
| transfer_percent | 转账百分比 |
| special_medal | 特殊勋章 |
| points | 积分 |
| level | 等级 |

### 2.2 VIP/SVIP兑换码处理逻辑

#### VIP兑换处理 (routes/redeem.js 第217-231行)

```javascript
case "vip":
  // 处理VIP兑换
  if (!user.vipExpireDate || user.vipExpireDate < now) {
    user.vipExpireDate = now;
  }
  user.vipExpireDate = addDays(user.vipExpireDate, redeemCode.value);
  // 非超级管理员与非管理员才更新角色
  if (user.role !== "superadmin" && user.role !== "admin") {
    user.role = "vip";
  }
  result = {
    type: "vip",
    expireDate: formatDateTime(user.vipExpireDate),
  };
  break;
```

#### SVIP兑换处理 (routes/redeem.js 第233-247行)

```javascript
case "svip":
  // 处理SVIP兑换
  if (!user.svipExpireDate || user.svipExpireDate < now) {
    user.svipExpireDate = now;
  }
  user.svipExpireDate = addDays(user.svipExpireDate, redeemCode.value);
  // 只有非超级管理员才更新角色
  if (user.role !== "superadmin") {
    user.role = "svip";
  }
  result = {
    type: "svip",
    expireDate: formatDateTime(user.svipExpireDate),
  };
  break;
```

## 3. 发现的问题

### 问题1: 角色类型不匹配 ⚠️

**位置**: `routes/redeem.js` 第224行和第240行

**问题描述**:
```javascript
// 第224行
if (user.role !== "superadmin" && user.role !== "admin") {
  user.role = "vip";
}

// 第240行
if (user.role !== "superadmin") {
  user.role = "svip";
}
```

这里使用的是**字符串**比较 (`"superadmin"`, `"admin"`, `"vip"`, `"svip"`)，但根据 `models/User.js` 第104-108行，`role` 字段是**Number类型**：
```javascript
role: {
  type: Number,
  enum: [0, 1, 2, 3, 4], // 0=普通用户，1=VIP，2=SVIP，3=管理员，4=超级管理员
  default: 0,
},
```

**影响**: 这个条件永远不会成立，导致：
1. VIP兑换码无法正确更新用户角色
2. SVIP兑换码无法正确更新用户角色

---

### 问题2: 过期后的VIP状态 ✅

**结论**: 到期后用户**不会**再是VIP

根据 `models/User.js` 第238-245行的 `isVip()` 方法：
```javascript
UserSchema.methods.isVip = function () {
  return (
    (this.role === 1 || this.role === 2) &&
    (this.vip_expire || this.vipExpireDate) &&
    (this.vip_expire > new Date() || this.vipExpireDate > new Date())
  );
};
```

虽然 `role` 字段可能还保留着 1 或 2，但 `isVip()` 方法会检查过期时间。如果过期时间在当前时间之前，方法会返回 `false`，用户就不再是VIP了。

同样的逻辑适用于 SVIP。

---

## 4. 建议修复方案

### 修复角色类型不匹配问题

修改 `routes/redeem.js` 第224-226行和第240-242行：

```javascript
// VIP兑换
// 非超级管理员(4)与非管理员(3)才更新角色
if (user.role !== 4 && user.role !== 3) {
  user.role = 1;  // VIP
}

// SVIP兑换
// 只有非超级管理员(4)才更新角色
if (user.role !== 4) {
  user.role = 2;  // SVIP
}
```
