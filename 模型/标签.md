# 标签管理接口与模型设计

为支持首页通过标签筛选日记，需要设计一套标签系统，包括标签数据模型、存储方式以及获取标签列表的接口。本设计基于现有日记模型中`tags`字段（JSON数组）的存储方式，建议将其规范化，建立独立的标签表和日记-标签关联表，以提高查询效率和扩展性。

---

## 1. 数据模型设计

### 1.1 标签表 `tags`

存储所有用户使用过的标签（全局唯一，大小写不敏感）。

| 字段名       | 类型     | 长度 | 是否可空 | 默认值                      | 说明                                 |
| ------------ | -------- | ---- | -------- | --------------------------- | ------------------------------------ |
| `id`         | bigint   | 20   | NO       | AUTO_INCREMENT              | 主键ID                               |
| `name`       | varchar  | 50   | NO       | -                           | 标签名称，唯一（建议统一小写存储）   |
| `use_count`  | int      | 11   | NO       | 0                           | 全局使用次数（所有日记中出现的次数） |
| `created_at` | datetime | -    | NO       | CURRENT_TIMESTAMP           | 首次创建时间                         |
| `updated_at` | datetime | -    | NO       | CURRENT_TIMESTAMP ON UPDATE | 最后更新时间                         |

**索引**：

- `name` 唯一索引
- `use_count` 索引（用于热门标签排序）

### 1.2 日记-标签关联表 `diary_tags`

多对多关联，记录每篇日记使用了哪些标签。

| 字段名       | 类型     | 长度 | 是否可空 | 默认值            | 说明                       |
| ------------ | -------- | ---- | -------- | ----------------- | -------------------------- |
| `id`         | bigint   | 20   | NO       | AUTO_INCREMENT    | 主键ID                     |
| `diary_id`   | bigint   | 20   | NO       | -                 | 日记ID，关联`diaries.id`   |
| `tag_id`     | bigint   | 20   | NO       | -                 | 标签ID，关联`tags.id`      |
| `created_at` | datetime | -    | NO       | CURRENT_TIMESTAMP | 关联时间（即日记发布时间） |

**索引**：

- 唯一索引 `(diary_id, tag_id)` 防止重复关联
- 索引 `tag_id` 用于查询某个标签下的日记

### 1.3 用户-标签统计表（可选，用于个人常用标签）

若需要统计每个用户对标签的使用频率，可增加此表。

| 字段名         | 类型     | 说明                   |
| -------------- | -------- | ---------------------- |
| `id`           | bigint   | 主键ID                 |
| `user_id`      | bigint   | 用户ID                 |
| `tag_id`       | bigint   | 标签ID                 |
| `use_count`    | int      | 该用户使用此标签的次数 |
| `last_used_at` | datetime | 最后使用时间           |

**索引**：`(user_id, use_count)` 用于获取用户的常用标签。

## 2. 标签使用逻辑（数据一致性）

### 2.1 新增/修改日记时的标签处理

1. 前端提交日记时，`tags`字段为标签名称数组（如 `["旅行","美食"]`）。
2. 后端处理：
   - 将每个标签名称转为小写（或保留原样但大小写不敏感），检查`tags`表中是否存在，不存在则插入新记录，`use_count`初始化为0。
   - 获取每个标签对应的`tag_id`。
   - 在`diary_tags`表中插入关联记录（若已存在则忽略，一般不会重复）。
   - 更新`tags`表的`use_count`：对于新增的关联，将对应标签的`use_count`加1（注意：如果是编辑日记，需要比较新旧标签差异，对删除的标签减1，新增的加1）。
   - 同时，若需要个人统计，更新`user_tags`表。

### 2.2 删除日记时的标签处理

- 删除日记时，同时删除`diary_tags`中的关联记录，并将对应标签的`use_count`减1。
- 若标签的`use_count`减至0，可保留（用于历史统计）或定期清理。

### 2.3 批量更新建议

对于高频操作，可使用事务保证一致性。

## 3. 接口设计

### 3.1 获取标签列表（全局热门标签）

```
GET /api/tags
```

**请求参数**：

- `type`（可选）：`global`（全局热门，默认）、`user`（用户常用）
- `user_id`（当type=user时必传）：用户ID
- `keyword`（可选）：搜索标签名称
- `page`：页码，默认1
- `page_size`：每页条数，默认20
- `sort`：排序方式，`hot`（按使用次数，默认）、`new`（按创建时间）、`name`（按名称）

**响应**：

```json
{
  "code": 200,
  "data": {
    "total": 200,
    "page": 1,
    "page_size": 20,
    "items": [
      {
        "id": 1,
        "name": "旅行",
        "use_count": 1234,
        "user_use_count": 56 // 当type=user时返回个人使用次数
      },
      {
        "id": 2,
        "name": "美食",
        "use_count": 987,
        "user_use_count": 12
      }
    ]
  }
}
```

### 3.2 获取标签详情

```
GET /api/tags/{id}
```

返回单个标签的详细信息，包括名称、使用次数等。

### 3.3 搜索标签

```
GET /api/tags/search?q=关键词
```

支持输入时实时搜索，返回匹配的标签列表（可限制返回数量，如10个）。用于前端输入时的自动补全。

## 4. 现有日记数据的迁移

若原有日记表已存在`tags` JSON字段，需编写脚本将数据迁移至新表：

1. 遍历所有日记，解析JSON字段，拆分成标签名称。
2. 对每个标签，插入`tags`表（若不存在）。
3. 在`diary_tags`表建立关联。
4. 更新`tags.use_count`（可使用临时统计后更新）。
5. 迁移完成后，可保留原`tags`字段或将其废弃。

---

## 5. 性能优化建议

- **热门标签缓存**：将全局热门标签列表缓存到Redis，定期更新（如每小时），减少数据库压力。
- **分页优化**：标签数量可能很大，使用游标分页或限制最大页数。
- **全文搜索**：若需要模糊搜索标签，可使用数据库的LIKE语句，或引入Elasticsearch。

## 6. 前端展示示例

在首页顶部或侧边增加“标签筛选”入口，点击展开标签云或列表，支持选择单个或多个标签，然后刷新日记列表。

**标签云样式**（按使用次数决定字体大小）：

#旅行(1234)  #美食(987)  #心情(654)  #日常(432)  #摄影(321)

## 7. 接口文档示例（Swagger）

```yaml
/api/tags:
  get:
    summary: 获取标签列表
    parameters:
      - name: type
        in: query
        schema:
          type: string
          enum: [global, user]
          default: global
      - name: user_id
        in: query
        schema: integer
        description: 当type=user时必传
      - name: keyword
        in: query
        schema: string
      - name: page
        in: query
        schema: integer
        default: 1
      - name: page_size
        in: query
        schema: integer
        default: 20
      - name: sort
        in: query
        schema:
          type: string
          enum: [hot, new, name]
          default: hot
    responses:
      200:
        description: 成功
        content:
          application/json:
            schema:
              type: object
              properties:
                total: integer
                page: integer
                page_size: integer
                items:
                  type: array
                  items:
                    type: object
                    properties:
                      id: integer
                      name: string
                      use_count: integer
                      user_use_count: integer
```

## 8. 总结

本设计通过将标签规范化存储，实现了高效的标签统计和筛选功能，满足首页按标签筛选日记的需求，并为后续个性化推荐、标签云展示等打下基础。接口简单易用，可扩展性强。
