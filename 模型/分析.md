# 日记分析模块设计（情感分析+主题挖掘+趋势统计）

对用户编写的日记进行深度分析，帮助用户了解自己的情绪变化、写作习惯、主题偏好等，提升自我认知和记录体验。本设计涵盖数据模型、分析维度、计算逻辑及接口，并提供可视化数据支持。

---

## 1. 分析维度概述

| 分析维度          | 说明                                               | 输出示例                 |
| ----------------- | -------------------------------------------------- | ------------------------ |
| **情感分析**      | 识别日记正文的情感倾向（积极/中性/消极）及强度     | 积极 0.85，消极 0.12     |
| **主题分类**      | 自动提取日记核心主题（如工作、生活、旅行、情感等） | ["生活", "情感"]         |
| **关键词提取**    | 提取最具代表性的名词/短语                          | ["周末", "朋友", "电影"] |
| **写作风格**      | 统计字数、句子数、平均句长、常用词汇等             | 字数 256，句子 12        |
| **时间分布**      | 按小时、星期、月份统计写作频率                     | 晚间写作占比 65%         |
| **情绪趋势**      | 按时间序列展示情感波动曲线                         | 折线图                   |
| **标签关联**      | 统计常用标签及其与情感的关联                       | "工作"标签常伴随消极情绪 |
| **天气/心情关联** | 分析天气、心情与情感的关系                         | 雨天更容易出现消极情绪   |

## 2. 数据模型设计

### 2.1 日记分析结果表 `diary_analysis`

存储每篇日记的分析结果（一次写入，可更新）。

| 字段名                | 类型        | 说明                                        |
| --------------------- | ----------- | ------------------------------------------- |
| `id`                  | bigint      | 主键ID                                      |
| `diary_id`            | bigint      | 日记ID，关联`diaries.id`                    |
| `user_id`             | bigint      | 用户ID（冗余，便于查询）                    |
| `sentiment`           | varchar(20) | 情感标签：positive/neutral/negative         |
| `sentiment_score`     | float       | 情感得分：-1.0到1.0，负值表示消极，正值积极 |
| `topics`              | json        | 主题列表，如["工作","压力"]                 |
| `keywords`            | json        | 关键词列表，如["加班","会议"]               |
| `word_count`          | int         | 正文总字数                                  |
| `sentence_count`      | int         | 句子数量                                    |
| `avg_sentence_length` | float       | 平均句长（字）                              |
| `created_at`          | datetime    | 分析时间                                    |
| `updated_at`          | datetime    | 更新时间                                    |

**索引**：`diary_id`唯一索引，`user_id`索引。

### 2.2 用户月度/周度统计表 `user_analysis_summary`

存储按时间聚合的分析结果，用于趋势图展示。

| 字段名             | 类型        | 说明                     |
| ------------------ | ----------- | ------------------------ |
| `id`               | bigint      | 主键ID                   |
| `user_id`          | bigint      | 用户ID                   |
| `date_type`        | varchar(10) | 统计类型：day/week/month |
| `stat_date`        | date        | 统计日期（如2026-03-01） |
| `diary_count`      | int         | 该时段日记数             |
| `avg_sentiment`    | float       | 平均情感得分             |
| `total_word_count` | int         | 总字数                   |
| `top_topics`       | json        | 主要主题及频次           |
| `top_keywords`     | json        | 主要关键词及频次         |
| `common_mood`      | json        | 常用心情及频次           |
| `common_weather`   | json        | 常用天气及频次           |
| `created_at`       | datetime    | 创建时间                 |

**索引**：`(user_id, date_type, stat_date)`唯一索引。

### 2.3 用户标签-情感关联表 `user_topic_sentiment`

用于分析不同主题的情感倾向。

| 字段名           | 类型        | 说明               |
| ---------------- | ----------- | ------------------ |
| `id`             | bigint      | 主键ID             |
| `user_id`        | bigint      | 用户ID             |
| `topic`          | varchar(50) | 主题名称           |
| `positive_count` | int         | 积极日记数         |
| `neutral_count`  | int         | 中性日记数         |
| `negative_count` | int         | 消极日记数         |
| `avg_sentiment`  | float       | 该主题平均情感得分 |
| `updated_at`     | datetime    | 最后更新时间       |

**索引**：`(user_id, topic)`唯一索引。

## 3. 分析计算逻辑

### 3.1 情感分析

- 使用预训练的情感分析模型（如BERT、TextBlob、百度AI开放平台等）对正文进行情感分类和得分计算。
- 若本地无法部署，可调用第三方API（需注意隐私）。
- 结果存入`sentiment`和`sentiment_score`。

### 3.2 主题分类

- 可采用LDA主题模型、TextRank或预训练分类器。
- 输出3-5个主题标签，每个标签带置信度（可选）。
- 存入`topics`字段（JSON数组）。

### 3.3 关键词提取

- 使用TF-IDF、TextRank或jieba分词提取关键词。
- 限制数量（如10个），存入`keywords`。

### 3.4 写作风格统计

- 字数：去除空白后字符数。
- 句子数：按句号、问号、感叹号分割。
- 平均句长：总字数/句子数。

### 3.5 聚合统计（定时任务）

- 每日凌晨，对前一日的日记进行聚合，更新`user_analysis_summary`（按天）。
- 每周/每月汇总同样方式更新周/月表。
- 同时更新`user_topic_sentiment`：遍历当天日记的主题，更新各主题的情感计数。

## 4. 接口设计

### 4.1 获取日记分析结果（单篇）

```
GET /api/diary/analysis/{diary_id}
```

**响应**：

```json
{
  "code": 200,
  "data": {
    "diary_id": 123,
    "sentiment": "positive",
    "sentiment_score": 0.82,
    "topics": ["生活", "朋友"],
    "keywords": ["周末", "聚会", "开心"],
    "word_count": 256,
    "sentence_count": 12,
    "avg_sentence_length": 21.3
  }
}
```

### 4.2 获取用户分析概览

```
GET /api/user/analysis/overview
```

返回用户整体统计数据：

```json
{
  "code": 200,
  "data": {
    "total_diaries": 156,
    "total_words": 38000,
    "avg_sentiment": 0.45,
    "positive_ratio": 0.62,
    "neutral_ratio": 0.28,
    "negative_ratio": 0.1,
    "top_topics": ["生活", "工作", "旅行"],
    "top_keywords": ["今天", "开心", "朋友"],
    "writing_times": {
      "morning": 12,
      "afternoon": 35,
      "evening": 89,
      "night": 20
    }
  }
}
```

### 4.3 获取情感趋势（按天/周/月）

```
GET /api/user/analysis/sentiment-trend?type=week&range=12
```

返回时间序列数据：

```json
{
  "code": 200,
  "data": {
    "labels": ["W1", "W2", "W3", ...],
    "values": [0.5, 0.6, 0.4, 0.7],
    "diary_counts": [5, 7, 4, 6]
  }
}
```

### 4.4 获取主题情感关联

```
GET /api/user/analysis/topic-sentiment
```

返回每个主题的情感分布：

```json
{
  "code": 200,
  "data": [
    {
      "topic": "工作",
      "positive": 12,
      "neutral": 8,
      "negative": 5,
      "avg": 0.2
    },
    {
      "topic": "生活",
      "positive": 45,
      "neutral": 12,
      "negative": 3,
      "avg": 0.7
    }
  ]
}
```

### 4.5 获取词云数据

```
GET /api/user/analysis/wordcloud?limit=50
```

返回关键词及其权重：

```json
{
  "code": 200,
  "data": [
    { "word": "开心", "weight": 0.85 },
    { "word": "周末", "weight": 0.72 }
  ]
}
```

## 5. 分析任务调度

- **实时分析**：用户写完日记并保存后，立即异步触发分析（消息队列），避免阻塞。
- **定时聚合**：每日凌晨2点，执行前一天的日记聚合，更新用户统计表和主题情感表。
- **重试机制**：分析失败的任务自动重试3次。

---

## 6. 技术实现建议

### 6.1 分析引擎

- **Python微服务**：独立部署分析服务，提供REST API，使用Flask/FastAPI。
- **模型加载**：预加载情感模型、主题模型，减少延迟。
- **缓存**：高频分析结果可缓存（如用户概览）。

### 6.2 数据库优化

- 分析结果表`diary_analysis`使用`diary_id`唯一索引，关联查询时注意索引。
- 统计表`user_analysis_summary`按用户+时间查询，建立联合索引。

### 6.3 隐私保护

- 分析过程仅在服务端进行，不存储用户原始文本（除非需要，可保留分析结果）。
- 如需调用第三方API，需脱敏处理（如去除姓名、地点等敏感信息）。

---

## 7. 前端展示建议

- **情绪曲线**：ECharts绘制折线图，展示情感变化。
- **词云**：使用`echarts-wordcloud`展示高频关键词。
- **主题分布**：饼图或柱状图展示各主题占比。
- **写作习惯**：雷达图展示不同时间段写作频率。
- **心情/天气关联**：热力图或散点图展示不同天气下的情感分布。

## 8. 数据示例（MySQL建表SQL）

```sql
-- 日记分析结果表
CREATE TABLE `diary_analysis` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `diary_id` bigint NOT NULL,
  `user_id` bigint NOT NULL,
  `sentiment` varchar(20) DEFAULT NULL,
  `sentiment_score` float DEFAULT NULL,
  `topics` json DEFAULT NULL,
  `keywords` json DEFAULT NULL,
  `word_count` int DEFAULT '0',
  `sentence_count` int DEFAULT '0',
  `avg_sentence_length` float DEFAULT '0',
  `created_at` datetime DEFAULT CURRENT_TIMESTAMP,
  `updated_at` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_diary_id` (`diary_id`),
  KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 用户月度/周度统计表
CREATE TABLE `user_analysis_summary` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `user_id` bigint NOT NULL,
  `date_type` varchar(10) NOT NULL COMMENT 'day/week/month',
  `stat_date` date NOT NULL,
  `diary_count` int NOT NULL DEFAULT '0',
  `avg_sentiment` float DEFAULT NULL,
  `total_word_count` int DEFAULT '0',
  `top_topics` json DEFAULT NULL,
  `top_keywords` json DEFAULT NULL,
  `common_mood` json DEFAULT NULL,
  `common_weather` json DEFAULT NULL,
  `created_at` datetime DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_type_date` (`user_id`,`date_type`,`stat_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 用户主题情感关联表
CREATE TABLE `user_topic_sentiment` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `user_id` bigint NOT NULL,
  `topic` varchar(50) NOT NULL,
  `positive_count` int NOT NULL DEFAULT '0',
  `neutral_count` int NOT NULL DEFAULT '0',
  `negative_count` int NOT NULL DEFAULT '0',
  `avg_sentiment` float DEFAULT NULL,
  `updated_at` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_topic` (`user_id`,`topic`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
