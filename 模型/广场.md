# 广场页面数据模型设计

广场页面用于展示公开日记，支持推荐、热门、最新、关注、同城等维度的筛选。基于已有的日记模型和用户模型，我们需要补充互动数据（点赞、评论）、用户关系（关注）、地理位置等，并设计相应的数据库表结构，以支持高效查询和扩展。

---

## 1. 核心表设计

### 1.1 日记表 `diaries`（扩展）

在已有的日记表基础上，增加用于广场展示的冗余字段和索引。

| 字段名          | 类型         | 说明                           |
| --------------- | ------------ | ------------------------------ |
| `id`            | bigint       | 主键ID                         |
| `user_id`       | bigint       | 作者ID，关联users表            |
| `title`         | varchar(200) | 标题                           |
| `content`       | longtext     | 正文（或预览）                 |
| `cover`         | varchar(500) | 封面图片URL                    |
| `images`        | json         | 正文图片列表（预览用）         |
| `tags`          | json         | 标签列表                       |
| `location`      | varchar(255) | 地点名称（用于同城）           |
| `location_city` | varchar(100) | 城市名称（冗余，便于同城筛选） |
| `is_public`     | tinyint(1)   | 是否公开：1=公开，0=私密       |
| `status`        | tinyint(1)   | 状态：1=正常，0=删除           |
| `like_count`    | int          | 点赞数                         |
| `comment_count` | int          | 评论数                         |
| `share_count`   | int          | 分享数                         |
| `view_count`    | int          | 阅读数（可选）                 |
| `score`         | float        | 热度评分（用于推荐排序）       |
| `created_at`    | datetime     | 发布时间                       |
| `updated_at`    | datetime     | 最后更新时间                   |

**索引建议**：

- `(is_public, status, created_at)` 用于最新公开日记
- `(is_public, status, like_count)` 用于热门（按点赞）
- `(is_public, status, comment_count)` 用于热门（按评论）
- `(is_public, status, score)` 用于推荐排序
- `(user_id, is_public, status)` 用于用户个人公开日记

### 1.2 用户表 `users`（扩展）

增加地理位置和社交计数。

| 字段名              | 类型         | 说明                 |
| ------------------- | ------------ | -------------------- |
| `id`                | bigint       | 主键ID               |
| `nickname`          | varchar(100) | 昵称                 |
| `avatar`            | varchar(500) | 头像URL              |
| `bio`               | varchar(500) | 个人简介             |
| `city`              | varchar(100) | 所在城市（用于同城） |
| `follower_count`    | int          | 粉丝数               |
| `following_count`   | int          | 关注数               |
| ...（其他已有字段） | ...          | ...                  |

**索引**：`city` 用于同城筛选。

### 1.3 关注表 `follows`

记录用户之间的关注关系。

| 字段名         | 类型                          | 说明           |
| -------------- | ----------------------------- | -------------- |
| `id`           | bigint                        | 主键           |
| `follower_id`  | bigint                        | 关注者用户ID   |
| `following_id` | bigint                        | 被关注者用户ID |
| `created_at`   | datetime                      | 关注时间       |
| UNIQUE KEY     | `(follower_id, following_id)` | 唯一组合       |

**索引**：

- `follower_id` 查询关注列表
- `following_id` 查询粉丝列表

### 1.4 点赞表 `likes`

记录用户对日记的点赞。

| 字段名       | 类型                  | 说明         |
| ------------ | --------------------- | ------------ |
| `id`         | bigint                | 主键         |
| `user_id`    | bigint                | 点赞用户ID   |
| `diary_id`   | bigint                | 日记ID       |
| `created_at` | datetime              | 点赞时间     |
| UNIQUE KEY   | `(user_id, diary_id)` | 防止重复点赞 |

### 1.5 评论表 `comments`

记录用户对日记的评论。

| 字段名       | 类型         | 说明                 |
| ------------ | ------------ | -------------------- |
| `id`         | bigint       | 主键                 |
| `user_id`    | bigint       | 评论用户ID           |
| `diary_id`   | bigint       | 日记ID               |
| `content`    | varchar(500) | 评论内容             |
| `like_count` | int          | 评论点赞数（可选）   |
| `status`     | tinyint      | 状态：1=正常，0=删除 |
| `created_at` | datetime     | 评论时间             |

**索引**：`(diary_id, created_at)` 用于获取日记的评论列表。

### 1.6 推荐/热度计算（可选）

若需个性化推荐，可设计用户行为表或使用外部搜索引擎。简单场景下，可使用`diaries`表中的`score`字段，定期按规则计算（如：`like_count*2 + comment_count*3 + share_count*5 + (now - created_at)权重`）并更新。

## 2. 广场查询逻辑

### 2.1 推荐

- 默认按 `score` 倒序，结合时间衰减。
- 可结合用户兴趣标签（需单独表），此处简化。

### 2.2 热门

- 按 `like_count` 或 `comment_count` 倒序，可限定时间范围（如近7天）。

### 2.3 最新

- 按 `created_at` 倒序。

### 2.4 关注

- 先查询用户关注的作者ID列表（`follows`表），再查询这些作者的公开日记，按时间倒序。
- SQL示例：

```sql
SELECT d.* FROM diaries d
INNER JOIN follows f ON d.user_id = f.following_id
WHERE f.follower_id = :current_user_id
  AND d.is_public = 1 AND d.status = 1
ORDER BY d.created_at DESC
LIMIT 20;
```

### 2.5 同城

- 根据当前用户所在城市，查询同城用户的公开日记。
- 需用户表有`city`字段，且用户公开了城市信息（可在用户隐私设置中控制）。

```sql
SELECT d.* FROM diaries d
INNER JOIN users u ON d.user_id = u.id
WHERE u.city = :user_city
  AND d.is_public = 1 AND d.status = 1
ORDER BY d.created_at DESC;
```

## 4. 索引与性能优化

- 所有外键字段（如`user_id`, `diary_id`）均需建立索引。
- 关注表使用复合唯一索引，避免重复关注。
- 点赞表使用复合唯一索引。
- 对`diaries`表常用查询字段（`is_public`, `status`, `created_at`, `like_count`, `score`）建立组合索引。
- 若数据量巨大，可考虑分表分库或使用Elasticsearch进行全文搜索和推荐排序。

---

## 5. 扩展考虑

- **隐私控制**：用户可设置是否公开城市，同城筛选需尊重用户设置。
- **屏蔽/拉黑**：可增加`blocks`表，广场查询时排除被屏蔽用户的日记。
- **举报机制**：增加`reports`表，用于处理违规内容。
- **推荐算法**：可基于用户行为（点赞、评论、停留时长）计算兴趣标签，个性化推荐。

---

本模型在已有日记和用户表的基础上，补充了互动表、关注表，并扩展了必要的冗余字段和索引，能够高效支持广场页面的各项功能。后续可根据业务发展调整。
