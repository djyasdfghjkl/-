# 日记模型设计（后端用）

基于您的需求（标题、日期、天气、心情、标签）以及之前设计稿中的高级功能（封面、签名、地点、图片等），我为您设计一个全面且扩展性强的日记数据模型。该模型适用于关系型数据库（如MySQL、PostgreSQL）或NoSQL（如MongoDB），并提供JSON Schema定义。

---

## 1. 核心需求分析

- **基础信息**：标题、正文、写作日期（可不同于创建时间）
- **元数据**：天气、心情、标签、地点、签名（一句话总结）
- **多媒体**：封面图片、正文图片列表
- **状态**：是否公开、是否置顶、是否删除（软删除）
- **关联**：所属用户ID、关联的倒数本事件ID（可选）
- **时间戳**：创建时间、最后修改时间
- **统计**：字数、阅读量、点赞数、评论数（若开放社交）

---

## 2. 数据库表设计（MySQL示例）

### 2.1 表名：`diaries`

| 字段名            | 类型     | 长度 | 是否可空 | 默认值                      | 说明                             |
| ----------------- | -------- | ---- | -------- | --------------------------- | -------------------------------- |
| `id`              | bigint   | 20   | NO       | AUTO_INCREMENT              | 主键ID                           |
| `user_id`         | bigint   | 20   | NO       | -                           | 所属用户ID，关联users表          |
| `title`           | varchar  | 200  | NO       | ''                          | 日记标题                         |
| `content`         | longtext | -    | NO       | ''                          | 正文内容（支持富文本）           |
| `diary_date`      | date     | -    | NO       | CURRENT_DATE                | 日记写作日期（可不同于创建时间） |
| `weather`         | varchar  | 50   | YES      | NULL                        | 天气（如“晴”、“多云”）           |
| `mood`            | varchar  | 50   | YES      | NULL                        | 心情（如“开心”、“平静”）         |
| `signature`       | varchar  | 200  | YES      | NULL                        | 一句话签名                       |
| `location`        | varchar  | 255  | YES      | NULL                        | 地点名称                         |
| `location_coords` | point    | -    | YES      | NULL                        | 地理位置坐标（若需精确）         |
| `cover`           | varchar  | 500  | YES      | NULL                        | 封面图片URL                      |
| `images`          | json     | -    | YES      | NULL                        | 正文图片URL数组（JSON格式）      |
| `tags`            | json     | -    | YES      | NULL                        | 标签数组（JSON格式）             |
| `is_public`       | tinyint  | 1    | NO       | 0                           | 是否公开：0=私密，1=公开         |
| `is_top`          | tinyint  | 1    | NO       | 0                           | 是否置顶：0=否，1=是             |
| `status`          | tinyint  | 1    | NO       | 1                           | 状态：0=删除，1=正常             |
| `word_count`      | int      | 11   | NO       | 0                           | 字数统计                         |
| `view_count`      | int      | 11   | NO       | 0                           | 阅读次数                         |
| `like_count`      | int      | 11   | NO       | 0                           | 点赞次数                         |
| `comment_count`   | int      | 11   | NO       | 0                           | 评论次数                         |
| `created_at`      | datetime | -    | NO       | CURRENT_TIMESTAMP           | 创建时间                         |
| `updated_at`      | datetime | -    | NO       | CURRENT_TIMESTAMP ON UPDATE | 最后修改时间                     |
| `event_id`        | bigint   | 20   | YES      | NULL                        | 关联的倒数本事件ID（可选）       |

### 2.2 索引建议

- 主键：`id`
- 外键索引：`user_id`
- 组合索引：`(user_id, diary_date)` 用于快速查询用户某天的日记
- 查询索引：`(user_id, is_public, status)` 用于公开日记查询
- 全文索引：`(title, content)` 支持搜索（MySQL需MyISAM或InnoDB 5.6+）

### 2.3 说明

- `tags` 和 `images` 使用JSON类型，便于存储可变数组，也可使用关联表实现（但JSON更简单）。
- `diary_date` 允许用户指定写作日期，便于补记过去日记。
- `location_coords` 若使用MySQL空间扩展，可存储经纬度用于地理查询。

## 4. 字段详细说明

| 字段               | 类型                        | 说明                                               |
| ------------------ | --------------------------- | -------------------------------------------------- |
| **标题**           | `title`                     | 必填，短文本，支持搜索                             |
| **正文**           | `content`                   | 必填，长文本，支持富文本（可存HTML/Markdown）      |
| **写作日期**       | `diary_date`                | 必填，用户可自定义，用于显示和统计                 |
| **天气**           | `weather`                   | 可选，建议预定义常用值（如“晴”、“多云”）或自由文本 |
| **心情**           | `mood`                      | 可选，可预定义表情或文字                           |
| **签名**           | `signature`                 | 可选，一句话心情短语                               |
| **地点**           | `location`                  | 可选，文字描述；如需地图显示可配合坐标             |
| **坐标**           | `location_coords`           | 可选，存储经纬度，便于地图展示                     |
| **封面**           | `cover`                     | 可选，一张代表性图片                               |
| **图片列表**       | `images`                    | 可选，多张图片，用于正文插图                       |
| **标签**           | `tags`                      | 可选，字符串数组，用于分类和筛选                   |
| **公开状态**       | `is_public`                 | 默认私密，公开后可在广场展示                       |
| **置顶**           | `is_top`                    | 用户可将重要日记置顶                               |
| **软删除**         | `status`                    | 1正常，0删除，避免物理删除                         |
| **字数**           | `word_count`                | 自动计算，可用于统计                               |
| **阅读/点赞/评论** | 统计字段                    | 若开放社交功能                                     |
| **时间戳**         | `created_at` / `updated_at` | 记录创建和修改时间                                 |
| **关联事件**       | `event_id`                  | 若日记与某个倒数本事件相关（如生日倒计时日记）     |

## 5. 使用建议

### 5.1 关系型数据库

- 创建表时注意字符集使用 `utf8mb4` 以支持emoji。
- `tags` 和 `images` 若使用JSON字段，查询时可能需要特定函数（如 `JSON_CONTAINS`）。若对标签查询频繁，可单独建立标签关联表（`diary_tags`）。

### 5.2 NoSQL（MongoDB）

- 可直接存储上述JSON结构，文档ID为主键。
- 索引：`user_id`, `diary_date`, `tags` 等。

### 5.3 API设计示例

- **创建日记**：POST `/api/diaries` 传入上述JSON（不含id和时间戳）
- **获取日记列表**：GET `/api/diaries?user_id=xxx&page=1&per_page=10` 返回数组及总数
- **获取单篇**：GET `/api/diaries/{id}`
- **更新**：PUT `/api/diaries/{id}` 传入部分字段
- **删除**：DELETE `/api/diaries/{id}`（软删除）

## 6. 扩展性考虑

- **加密日记**：若需高级隐私，可增加 `is_encrypted` 字段和加密内容存储。
- **版本历史**：可额外建表存储日记修改历史。
- **关联多媒体**：若图片较多，可考虑单独图片表，此处用URL数组简化。
- **模板**：支持日记模板，可增加 `template_id` 字段。
