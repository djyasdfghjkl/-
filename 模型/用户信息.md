# 用户信息模型（后端用）

为用户系统设计一个全面且可扩展的数据模型，涵盖基本信息、认证方式、第三方登录、个性化设置、统计数据和勋章等。该模型适用于关系型数据库（如MySQL、PostgreSQL），并提供JSON Schema定义。

---

## 1. 核心需求分析

- **基础信息**：用户ID、昵称、头像、性别、生日、个人简介
- **认证方式**：手机号、邮箱、密码（哈希存储），支持多端登录
- **第三方登录**：微信、QQ、抖音、快手等平台的openid/unionid
- **状态**：账号状态（正常/禁用/冻结）、角色（普通/VIP/管理员）、VIP过期时间
- **统计**：日记总数、总字数、获得点赞数、粉丝数、关注数
- **个性化设置**：主题偏好、字体大小、通知开关等（JSON存储）
- **勋章系统**：已获得勋章列表及获得时间
- **时间戳**：注册时间、最后登录时间、资料更新时间

## 2. 数据库表设计（MySQL示例）

### 2.1 表名：`users`

| `phone_verified`  | tinyint  | 1    | NO       | 0                           | 手机号是否已验证                                 |

| `diary_count`     | int      | 11   | NO       | 0                           | 日记总数                                         |

| `like_count`      | int      | 11   | NO       | 0                           | 收到的点赞数                                     |
| `follower_count`  | int      | 11   | NO       | 0                           | 粉丝数                                           |
| `following_count` | int      | 11   | NO       | 0                           | 关注数                                           |
| `settings`        | json     | -    | YES      | NULL                        | 个性化设置（JSON对象）                           |
| `medals`          | json     | -    | YES      | NULL                        | 勋章列表，格式见下文                             |
| `last_login_at`   | datetime | -    | YES      | NULL                        | 最后登录时间                                     |
| `last_login_ip`   | varchar  | 45   | YES      | NULL                        | 最后登录IP                                       |
| `created_at`      | datetime | -    | NO       | CURRENT_TIMESTAMP           | 注册时间                                         |
| `updated_at`      | datetime | -    | NO       | CURRENT_TIMESTAMP ON UPDATE | 资料更新时间                                     |

### 2.2 索引建议

- 主键：`id`
- 唯一索引：`uuid`, `username`, `phone`, `email`, `wx_openid`, `qq_openid`, `douyin_openid`, `kuaishou_openid`
- 普通索引：`status`, `role`, `created_at`

### 2.3 说明

- `uuid` 用于对外暴露，避免泄露自增ID。
- 第三方登录字段支持多平台，可根据实际平台增减。
- `settings` JSON字段存储用户个性化设置，如主题偏好（基础/机甲/暗黑等）、字体大小、通知开关等。
- `medals` JSON字段存储用户获得的勋章信息，格式示例：

```json
[
  { "medal_id": 1, "obtained_at": "2025-01-01T12:00:00Z" },
  { "medal_id": 2, "obtained_at": "2025-02-15T08:30:00Z" }
]
```

| **用户名**       | `username`                        | 可选，用户自定义唯一登录名                     |
| **昵称**         | `nickname`                        | 必填，显示名称                                 |

| **手机号**       | `phone`                           | 唯一，可用于登录                               |
| **手机验证**     | `phone_verified`                  | 是否已验证                                     |

## 5. 使用建议

### 5.1 密码安全

- 使用 `bcrypt` 或 `Argon2` 直接哈希，无需单独存储 `salt` 字段。
- 密码字段可为空，表示用户通过第三方登录注册，后续可引导设置密码。

### 5.2 第三方登录

- 每个平台对应的openid需唯一索引，确保一个平台账号只能绑定一个用户。
- unionid 可用于跨平台识别同一用户（如微信开放平台）。

### 5.3 统计字段

- `diary_count`, `word_count` 等可在写入日记时实时更新，也可定时任务汇总。
- 若社交功能复杂，可单独建粉丝关系表，此处只保留计数。

### 5.4 设置存储

- 使用JSON字段便于灵活扩展，无需频繁修改表结构。
- 设置项应与前端主题等保持一致，便于恢复用户偏好。

### 5.5 勋章存储

- 勋章ID对应勋章定义表（`medals`），此处只存储用户已获得的勋章ID及时间。
- 也可用单独的用户勋章关联表，但JSON简化了查询（若查询不多）。

## 6. API设计示例

- **注册**：POST `/api/users` 传入 `nickname`, `phone`/`email`, `password` 或第三方code
- **登录**：POST `/api/auth/login` 支持手机号/邮箱/用户名+密码，或第三方code
- **获取用户信息**：GET `/api/users/{uuid}` 返回用户公开信息（含统计、勋章）
- **更新资料**：PUT `/api/users/{uuid}` 可更新昵称、头像、性别、生日、简介、设置等
- **修改密码**：POST `/api/users/{uuid}/password` 需旧密码验证
- **绑定手机/邮箱**：POST `/api/users/{uuid}/bind-phone` 等
- **绑定第三方**：POST `/api/users/{uuid}/bind-thirdparty` 传入平台和code

## 7. 扩展性考虑

- **用户成长体系**：可增加积分、等级字段。
- **付费订阅**：增加 `vip_type` 区分不同会员等级。
- **黑名单**：单独建表存储用户拉黑关系。
- **设备管理**：记录用户登录设备，用于安全控制。

该用户信息模型覆盖了基本认证、第三方登录、个性化设置和勋章系统，可满足日记类App的需求，并为未来社交、会员等功能留出扩展空间。根据实际业务可调整字段。
