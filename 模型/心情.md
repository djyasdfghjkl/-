# 心情模块设计

心情模块用于在写日记前选择当前心情，支持预设心情和用户自定义心情，并可关联表情包图标，让日记记录更生动、个性化。

---

## 1. 功能需求

- **预设心情库**：提供一套默认心情（如开心、平静、难过、生气等），每个心情包含名称和图标（Emoji 或自定义表情包）。
- **用户自定义心情**：允许用户创建自己的心情，包括自定义名称和选择图标（可从系统表情包或上传图片）。
- **心情与表情包关联**：心情图标可使用系统 Emoji、内置表情包或用户上传的自定义表情。
- **心情使用记录**：统计每种心情被选用的次数，用于推荐或排序。
- **心情标签/分类**：可对心情进行分类（如积极、消极、日常等），便于筛选。
- **多端同步**：用户自定义心情跨设备同步。

---

## 2. 数据模型设计

### 2.1 心情基础表 `moods`

存储所有心情（包括预设和用户自定义）。

| 字段名        | 类型     | 长度 | 是否可空 | 默认值                      | 说明                                          |
| ------------- | -------- | ---- | -------- | --------------------------- | --------------------------------------------- |
| `id`          | bigint   | 20   | NO       | AUTO_INCREMENT              | 主键ID                                        |
| `uuid`        | varchar  | 36   | NO       | UUID()                      | 对外唯一标识                                  |
| `name`        | varchar  | 50   | NO       | -                           | 心情名称（如“开心”）                          |
| `description` | varchar  | 255  | YES      | NULL                        | 心情描述（可选）                              |
| `icon_type`   | tinyint  | 1    | NO       | 1                           | 图标类型：1=Emoji，2=内置表情包，3=自定义图片 |
| `icon_value`  | varchar  | 500  | NO       | -                           | 图标值：Emoji字符、表情包ID或图片URL          |
| `category_id` | int      | 11   | YES      | NULL                        | 心情分类ID（可选）                            |
| `is_system`   | tinyint  | 1    | NO       | 0                           | 是否为系统预设：1=是，0=用户自定义            |
| `user_id`     | bigint   | 20   | YES      | NULL                        | 创建者用户ID（用户自定义时不为空）            |
| `status`      | tinyint  | 1    | NO       | 1                           | 状态：1=正常，0=禁用                          |
| `use_count`   | int      | 11   | NO       | 0                           | 全局使用次数                                  |
| `sort_order`  | int      | 11   | YES      | 0                           | 排序权重（系统预设可控制顺序）                |
| `created_at`  | datetime | -    | NO       | CURRENT_TIMESTAMP           | 创建时间                                      |
| `updated_at`  | datetime | -    | NO       | CURRENT_TIMESTAMP ON UPDATE | 更新时间                                      |

**索引**：

- `uuid` 唯一索引
- `user_id` 索引
- `is_system` 索引
- `category_id` 索引

### 2.2 心情分类表 `mood_categories`（可选）

| 字段名       | 类型    | 长度 | 说明                         |
| ------------ | ------- | ---- | ---------------------------- |
| `id`         | int     | 11   | 主键ID                       |
| `name`       | varchar | 50   | 分类名称（如“积极”、“消极”） |
| `icon`       | varchar | 200  | 分类图标                     |
| `sort_order` | int     | 11   | 排序权重                     |
| `is_active`  | tinyint | 1    | 是否启用                     |

### 2.3 用户心情使用记录表 `user_mood_usage`

记录用户每次写日记选择的心情，用于个性化推荐和统计。

| 字段名       | 类型     | 长度 | 说明                       |
| ------------ | -------- | ---- | -------------------------- |
| `id`         | bigint   | 20   | 主键ID                     |
| `user_id`    | bigint   | 20   | 用户ID                     |
| `mood_id`    | bigint   | 20   | 心情ID                     |
| `diary_id`   | bigint   | 20   | 日记ID（可选，关联的日记） |
| `created_at` | datetime | -    | 记录时间                   |

**索引**：`(user_id, mood_id)`，`(user_id, created_at)`

### 2.4 用户自定义心情图标表（可选，若用icon_type=3直接存URL则不需要）

若用户可上传图片作为心情图标，可单独存储图片信息，或直接使用对象存储URL。推荐直接存储URL。

### 2.5 与现有日记模型的集成

在日记表 `diaries` 中增加字段：

- `mood_id`：bigint，关联的心情ID（若选择心情）
- 原有 `mood` 字段可保留或废弃，建议统一使用 `mood_id`。

## 3. 接口设计

### 3.1 心情基础接口

#### 获取心情列表

```
GET /api/moods
```

**请求参数**：

- `category_id`（可选）：分类ID
- `type`（可选）：系统预设/自定义/all，默认all
- `keyword`（可选）：搜索关键词
- `page`：页码，默认1
- `page_size`：每页条数，默认20

**响应**：

```json
{
  "code": 200,
  "data": {
    "total": 100,
    "items": [
      {
        "id": "mood_uuid",
        "name": "开心",
        "icon_type": 1,
        "icon_value": "😊",
        "is_system": true,
        "use_count": 1234,
        "user_use_count": 56 // 当前用户使用次数（可选）
      }
    ]
  }
}
```

#### 获取心情详情

```
GET /api/moods/{uuid}
```

#### 获取常用心情（用户高频使用）

```
GET /api/user/moods/frequent
```

返回当前用户使用最多的心情列表。

#### 获取推荐心情（基于当前时间/场景）

```
GET /api/moods/recommend
```

可结合时间段（如早上推荐“活力”）或节假日推荐。

### 3.2 用户自定义心情接口

#### 创建自定义心情

```
POST /api/user/moods
```

**请求体**：

```json
{
  "name": "困成狗",
  "icon_type": 2,
  "icon_value": "emoji_cat_sleep" // 可以是表情包ID或Emoji
}
```

若`icon_type=3`且上传图片，需使用`multipart/form-data`上传文件。

**处理逻辑**：

- 校验名称是否已存在（同一用户下心情名称唯一）
- 若图标使用表情包，需验证表情包ID是否存在
- 若上传图片，保存到对象存储，生成URL
- 记录`user_id`，`is_system=0`

#### 修改自定义心情

```
PUT /api/user/moods/{uuid}
```

可修改名称、图标。

#### 删除自定义心情

```
DELETE /api/user/moods/{uuid}
```

软删除（将状态置为0），同时需检查是否被日记引用（可提示用户）。

#### 获取用户自定义心情列表

```
GET /api/user/moods/custom
```

### 3.3 心情与日记关联接口

#### 写日记时选择心情（已在日记准备页面集成）

前端在日记准备页面选择心情后，提交日记时携带 `mood_id`。

#### 批量获取心情使用统计

```
GET /api/moods/stats
```

可返回全局热门心情、用户常用心情等。

## 4. 集成到现有日记准备页面

在原有日记准备页面中，心情选择部分增强为：

- **横向滚动的心情图标**：展示预设心情（系统心情+用户自定义心情混合）。
- **每个心情项**：显示图标和名称（可选），选中时高亮。
- **“更多”按钮**：点击展开完整心情选择面板，支持分类筛选、搜索、自定义。
- **自定义入口**：在面板中提供“新建心情”按钮，弹出表单填写名称和选择图标（支持Emoji键盘、内置表情包选择、上传图片）。
- **已选心情预览**：在签名输入上方显示当前选中的心情。

## 5. 心情图标资源管理

- **Emoji**：直接使用Unicode字符，前端渲染。
- **内置表情包**：使用Lottie或静态图片，可引用之前设计的表情包模块。
- **用户上传图片**：保存到对象存储，需限制格式（jpg/png/gif）和大小（<1MB），并生成缩略图。

---

## 6. 统计与推荐

- **每日心情分布**：统计用户一周/一月的心情变化，可在统计页面展示。
- **心情与天气关联**：可分析天气与心情的关联（若日记记录了天气）。
- **心情标签**：可为心情添加标签（如“开心”可关联“积极”），便于分类推荐。

  ├── user_id -> users.id

## 9. 总结

该心情模块设计实现了：

- 预设心情库与用户自定义心情结合
- 支持Emoji、内置表情包、上传图片三种图标类型
- 使用频率统计与推荐
- 与日记模型无缝集成
- 提供完整的API接口和交互建议

用户可以在写日记前轻松选择心情，并自由创建个性化心情，极大丰富日记的情感表达。
