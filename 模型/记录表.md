# 请求来源记录中间件设计

在每次HTTP请求时，自动记录请求的详细信息（包括来源、IP、用户代理等），便于后续统计、审计和调试。以下是一个简单但字段详细的实现方案，适用于Node.js（Express/Koa）环境，其他语言类似。

---

## 1. 需要记录的字段

| 字段            | 说明                         | 获取方式                                                 |
| --------------- | ---------------------------- | -------------------------------------------------------- |
| `timestamp`     | 请求时间                     | `new Date()`                                             |
| `method`        | 请求方法（GET/POST等）       | `req.method`                                             |
| `url`           | 完整请求URL                  | `req.originalUrl` 或 `req.url`                           |
| `referer`       | 来源页面                     | `req.headers.referer` 或 `req.headers.referrer`          |
| `user_agent`    | 用户代理字符串               | `req.headers['user-agent']`                              |
| `ip`            | 客户端IP地址                 | `req.ip` 或 `req.connection.remoteAddress`（需处理代理） |
| `host`          | 请求的Host                   | `req.headers.host`                                       |
| `query`         | URL查询参数                  | `req.query`（JSON字符串）                                |
| `body`          | 请求体（可选，敏感信息脱敏） | `req.body`（需body-parser）                              |
| `user_id`       | 登录用户ID（如有）           | `req.user?.id` 或从session获取                           |
| `session_id`    | 会话ID                       | `req.sessionID` 或生成唯一ID                             |
| `response_time` | 响应耗时（ms）               | 记录开始和结束时间                                       |

## 2. Express中间件示例

```javascript
// request-logger.js
const fs = require("fs");
const path = require("path");

// 简单日志写入函数（可替换为数据库或日志库）
function writeLog(logEntry) {
  const logFile = path.join(
    __dirname,
    "logs",
    `requests-${new Date().toISOString().slice(0, 10)}.log`,
  );
  const logLine = JSON.stringify(logEntry) + "\n";
  fs.appendFile(logFile, logLine, (err) => {
    if (err) console.error("日志写入失败", err);
  });
}

// 获取真实IP（考虑代理）
function getClientIp(req) {
  const forwarded = req.headers["x-forwarded-for"];
  if (forwarded) {
    return forwarded.split(",")[0].trim();
  }
  return req.connection.remoteAddress || req.socket.remoteAddress;
}

// 日志中间件
function requestLogger(req, res, next) {
  const startTime = Date.now();

  // 记录请求基础信息
  const logEntry = {
    timestamp: new Date().toISOString(),
    method: req.method,
    url: req.originalUrl || req.url,
    referer: req.headers.referer || req.headers.referrer || "",
    user_agent: req.headers["user-agent"] || "",
    ip: getClientIp(req),
    host: req.headers.host || "",
    query: JSON.stringify(req.query || {}),
    // 敏感字段可脱敏，如只记录长度
    body: req.method === "POST" ? "[Recorded]" : "",
    user_id: req.user ? req.user.id : null,
    session_id: req.session ? req.session.id : null,
  };

  // 监听响应结束，记录耗时和状态码
  res.on("finish", () => {
    const duration = Date.now() - startTime;
    logEntry.status = res.statusCode;
    logEntry.duration_ms = duration;
    logEntry.response_size = res.get("Content-Length") || null;

    // 异步写入（避免阻塞）
    setImmediate(() => {
      writeLog(logEntry);
    });
  });

  next();
}

module.exports = requestLogger;
```

**使用方式**：

```javascript
const express = require("express");
const requestLogger = require("./request-logger");

const app = express();
app.use(requestLogger); // 放在所有路由之前

// ... 其他路由
```

## 3. 扩展建议

### 3.1 记录请求体（谨慎）

如需记录POST请求体，需在body-parser之后获取：

```javascript
app.use(express.json());
app.use((req, res, next) => {
  if (req.method === "POST") {
    req.rawBody = JSON.stringify(req.body); // 可在后续中间件中使用
  }
  next();
});
```

注意：避免记录密码等敏感信息，可提前脱敏（如替换为`***`）。

### 3.2 使用日志库

推荐使用 `winston` 或 `pino` 等专业日志库，支持分级、多输出（文件/数据库/控制台）。

### 3.3 性能考虑

- 异步写入，避免阻塞请求。
- 若流量大，使用消息队列（如RabbitMQ、Kafka）异步处理日志。
- 定期归档旧日志。

### 3.4 客户端来源分析

从 `user_agent` 可解析出操作系统、浏览器、设备类型（可用`ua-parser-js`库）。

## 4. 其他语言实现

- **PHP**：在入口文件（如`index.php`）记录 `$_SERVER` 信息。
- **Python**（Flask）：使用 `before_request` 和 `after_request` 装饰器。
- **Java**（Spring Boot）：使用 `HandlerInterceptor` 或 `Filter`。

## 6. 简单总结

以上中间件能够记录每次请求的详细信息，包括来源（referer）、IP、用户代理等，字段详细且实现简单。可根据实际需求调整记录内容，如增加数据库写入、敏感信息过滤等。此方案适用于中小型应用，易于集成和扩展。
